Viper: кто что делает

Практическая №4: мини-маркетплейс (БД в 3НФ → API → десктоп). Делим на двоих: Человек A — архитектура и бэкенд, Человек B — база данных и фронт. Оценка в часах, чтобы было видно, что нагрузка примерно 50/50.

A: архитектура + API ≈ 37 чB: БД + UI ≈ 37 ч
Человек A

Архитектура + Бэкенд

37 ч
Архитектура решения4 ч
  • Структура солюшена, проект Viper.Contracts (общие DTO для API и десктопа)
  • Слои в API: Controllers → Services → ViperDbContext
  • Глобальная обработка ошибок (ProblemDetails), Swagger с JWT-кнопкой
Регистрация и вход6 ч
  • Рега: логин, пароль, повтор пароля — сверка на сервере
  • Хеш пароля (PasswordHasher / BCrypt), никакого открытого текста
  • JWT, роли User/Admin, политики [Authorize(Roles="Admin")]
Каталог (публичный)4 ч
  • Список товаров: поиск по названию, фильтр по категории, цена от–до
  • Карточка товара; рейтинг считается AVG(Rating) по отзывам
  • Категории, ПВЗ — чтение без авторизации
Корзина + избранное5 ч
  • Добавить / изменить количество / удалить, итоговая сумма
  • Проверка остатка на складе и флага «доступен» (не дать заказать 1488 из 3)
  • Избранное без дублей, «перенести в корзину»
Заказы — главная логика8 ч
  • «Купить сейчас» и «оформить корзину» через один сервис
  • Правило 600 ₽: меньше — только ПВЗ; проверка на сервере, не в UI
  • Транзакция: снапшот цены в OrderItems.UnitPrice, списание остатка, очистка корзины
  • История своих заказов с сортировкой по дате, чужие — 403/404
Отзывы2 ч
  • Читать — всем, писать — авторизованным, оценка 1–5, дата
Админские эндпоинты4 ч
  • CRUD товаров, вкл/выкл товара, категории, ПВЗ
  • Все заказы + смена статуса, удаление отзыва
HTTP-клиент для десктопа4 ч
  • IApiClient в десктопе: типизированные методы под каждый эндпоинт, хранение токена, обработка 401/400
  • Интерфейс выкладывается рано, чтобы B мог верстать экраны на заглушке
Человек B

База данных + Фронт

37 ч
Проектирование БД в 3НФ3 ч

Каркас десктопа3 ч

  • Состояние сессии: гость / юзер / админ — что показывать
Вход / регистрация2 ч
Каталог + карточка товара7 ч
  • Сетка товаров с фото, поиск, фильтры категория и цена
  • Карточка: описание, остаток, рейтинг, отзывы, форма отзыва, ♥, «в корзину», «купить сейчас»
Корзина + избранное4 ч
Оформление заказа3 ч
  • Выбор доставка/ПВЗ (UI повторяет правило 600 ₽, но решает сервер), адрес, список ПВЗ
Мои заказы + детали заказа3 ч
Админка6 ч
  • Товары (форма с выбором картинки, вкл/выкл), категории, ПВЗ
  • Все заказы со сменой статуса, модерация отзывов
Важно про WPF. В задании сказано WPF, а у вас Viper.Desktop на Avalonia (WPF не работает на macOS). Логика та же — MVVM + HTTP к API — но лучше заранее спросить преподавателя, засчитают ли Avalonia.

Порядок работы

Этап 0 · вместе · 1 пара

Согласовать ER-схему и список эндпоинтов с DTO. Это контракт: дальше каждый работает у себя и не ждёт другого.

Этап 1 · параллельно

B: сущности, DbContext, миграция, сиды — отдаёт первым, A на этом строит сервисы.
A: каркас API, Contracts, авторизация, интерфейс IApiClient.

Этап 2 · параллельно

A: эндпоинты по порядку: каталог → корзина → заказы → админка.
B: экраны на заглушке IApiClient, потом подключает реальный клиент.

Что каждый объясняет на защите

A

Слои и почему WPF/Avalonia не ходит в БД. Как хешируется пароль и устроен JWT. Почему правило 600 ₽ и проверка остатка на сервере. Транзакция оформления заказа и снапшот цены.

B

ER-схема и почему она в 3НФ. Почему рейтинг считается, а не хранится. Индексы и ограничения. MVVM: ViewModel, команды, биндинги, как экран меняется для гостя/юзера/админа.
